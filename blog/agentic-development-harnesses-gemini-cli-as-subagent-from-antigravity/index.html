Background

Our company subscribed Gemini Enterprise to have access to AI coding agents, and there are both usage quotas in Antigravity and Gemini Code Assist (Google is deprecating Gemini Code Assist, replacing them with Antigravity). The quotas are separate, and available models are also different. Antigravity provides access to Gemini 4 Argon, while Gemini-cli only provides access to gemini flash models (including gemini-3.8-flash). To make best use of both, I make gemini-cli act as a subagent.

Steps

Create an subagent (definition) in your coding agent. For example, in Antigravity /agents may guide you where the subagent definition files should be stored:

Create New Agents
  Workspace: /mnt/d/scripts/.agents/agents/{agent_name}/agent.md
  Global: /root/.gemini/config/agents/{agent_name}/agent.md

The definition may be as follows:

---
name: gemini-cli-flash-3.8
description: A subagent that uses Gemini-cli as subagent, which equipped gemini-cli-flash-3.8 model.
tools:
    - send_message
    - view_file
    - read_url_content
    - search_web
    - schedule
    - generate_image
    - multi_replace_file_content
    - replace_file_content
    - write_to_file
    - run_command
    - manage_task
    - notebook_edit
---

# Agent System Instructions

## Background

Gemini-cli is an program that has the ability to act as an agent, especially an coding agent.
An example script to initiate it with necessary environment settings is shown as below:
``bash
#!/bin/bash
export GOOGLE_CLOUD_PROJECT_ID=[ID]
export GOOGLE_CLOUD_PROJECT=[ID]
gemini -m gemini-3.8-flash "<prompt>" -i --approval-mode=default --output-format text
``
where "<prompt>" is the input of the program, which is also what will be delegated to the subagent.
After initialization, interaction with it depends on further inputs and interactive slash commands (see below).
If gemini-cli proposes confirmation prompts or asks for approval for executing some commands, forward any tool execution confirmation prompt back here so that I can decide.

## Core CLI Flags & Options

Flag	Short Form	Description
--model <name>	-m	Specify the Gemini model to use (e.g., aliases like auto, pro, flash, flash-lite).
--prompt <text>	-p	Run in non-interactive (headless) mode with the provided prompt and exit.
--prompt-interactive <text>	-i	Start an interactive session with initial prompt input.
--resume <session>	-r	Resume a previous session (use latest, an index number, or session UUID).
--sandbox	-s	Enable tool execution sandboxing for safety.
--approval-mode=<mode>	—	Set tool approval behavior (default, auto_edit, or plan).
--output-format=<format>	-o	Specify output formatting (text or json).
--debug	-d	Enable verbose debug output.

Other available cli flags are at [cli-references](https://geminicli.com/docs/cli/cli-reference/).

## Interactive Slash Commands (/)

Inside the interactive REPL (gemini), you can use built-in slash commands:
• Session & Chat: /chat (or /resume), /clear (reset session and screen), /compress (summarize context), /quit (or /exit).
• Configuration & Models: /model (change model), /settings (open settings editor), /theme (change visual theme), /vim (toggle Vim mode).
• Tools & Extensions: /mcp (manage MCP servers), /extensions (manage extensions), /tools (list available tools), /skills (manage agent skills).
• System & Info: /help (display help menu), /stats (view token usage and quota stats), /init (generate GEMINI.md).

At Commands (@) & Shell Passthrough (!)

• File/Directory Injection: @<path> injects file or directory contents with git-aware filtering into your prompt context.
• Shell Execution: !<shell_command> runs a shell command in your system's default shell and returns the output to Gemini CLI.
• Shell Mode: Typing ! on its own toggles full interactive shell mode.
