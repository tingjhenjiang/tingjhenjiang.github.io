Build A Multi-node K3S Cluster With Windows 11 WSL2

2026-07-25
  • #DevOps
  • #Infrastructure
  • #Windows
  • #WSL
  • #Kubernetes

Background

I’d like to have a kubernetes cluster, either for routine tasks or for practice. However, the cost of a kubernetes cluster on public clouds is often high for development (before formal deployments). Besides, I’d like to have a Apache Spark cluster for data processing (move data from on-premise to public cloud), and therefore an on-premise kubernetes cluster to achieve these goals is preferred.

Prerequistes

  • Windows 11
  • A On-premise Network, with at least two computers.
  • A common storage (samba shared drive is used here)

Steps

Enable WSL 2 And Create a Hyper-V Bridged Network Adapter

  • Hyper-V and WSL is enabled installed in Windows 11 (search in settings for add Windows features)

  • in Powershell:

    • Run wsl --update to install and update WSL.

    • Run Get-NetAdapter | Sort-Object Name to get all names of network interfaces.

    • Choose one of your network adapters, get its name, and run:

      New-VMSwitch -Name "WSLBridge" -NetAdapterName "乙太網路" -AllowManagementOS $true

      where the value of NetAdapterName ("乙太網路" here) should be the name of your network adapter.

    • Run Get-VMSwitch to check the status, and it should be something like:

      Name           SwitchType NetAdapterInterfaceDescription
----           ---------- ------------------------------
Default Switch Internal
WSLBridge      External   Realtek PCIe GbE Family Controller

    • The WSLBridge would be your network adapter from now on. It has the same MAC address as your original network adapter.

  • Modify and copy the following .wslconfig texts and save as your %UserProfile%.wslconfig in Windows host:

    [wsl2]
networkingMode=bridged
vmSwitch=WSLBridge
memory=30GB
processors=12
swap=15GB
swapfile=R:\\temp\\wsl-swap.vhdx
dnsTunneling=false
nestedVirtualization=true
ipv6=true
dhcp=true
localhostforwarding=true
macAddress=00-15-5D-XX-XX-XX

[experimental]
autoMemoryReclaim=dropCache
hostAddressLoopback=true
sparseVhd=true

    where the macAddress might be better to have 00-15-5D prefix to indicate it’s an virtual instance. XX-XX-XX might changed to what is close to the macaddress of your network adapter.

  • Why not using networkingMode=mirrored? Because k3s forwards traffics using iptable, and in networkingMode=mirrored there is still standard L4 port forwarding, and mirrored networking mode only enable the listening ports not being interfered by port forwards.

  • Prepare the following text file to be saved as your /etc/wsl.conf in WSL:

    [network]
generateResolvConf=false
hostname=somehostname-wsl

[boot]
systemd=true

[gpu]
enabled=true

[interop]
enabled=true

[time]
useWindowsTimezone=true

    where hostname can be changed to your preferred one.

Installation on K3S Master Node (control-plane)

  • Install the node to act as BOTH a master (control-plane) and a worker node:

    curl -sfL https://get.k3s.io | sh -

  • Get the cluster token and IP:

    sudo cat /var/lib/rancher/k3s/server/node-token

  • Install the node to act as master node only:

    curl -sfL https://get.k3s.io | sh -s - server --node-taint CriticalAddonsOnly=true:NoSchedule

Installation on K3S Worker Node

  • Run the following command in WSL of the worker node:
curl -sfL https://get.k3s.io | K3S_URL=https://[IP]:[PORT] K3S_TOKEN=k3stoken sh -

where the k3stoken come from previous step in k3s cluter master node installation, or if you forget it, you may use sudo cat /var/lib/rancher/k3s/server/token to find out; and the PORT can be found in previous steps, or with sudo ss -tulpn | grep k3s. IP should be the network IP address of the master node of K3s cluster.

  • If typo or mistakes happened, you may check the variables through:

    sudo cat /etc/systemd/system/k3s-agent.service.env

    it will outputs something like:

    K3S_TOKEN='[K3S_token]'
K3S_URL='https://[IP]:6443'

Check Running Status of the Cluster and Debug

  • Run the command on master node:

    kubectl describe node

    to check if worker node successfully joined the cluster.

Configure the Cluster - Install Headlamp

  • Follow the installation guides on installing headlamp using Helm.

    helm repo add headlamp https://kubernetes-sigs.github.io/headlamp/
helm install my-headlamp headlamp/headlamp --namespace kube-system

  • After installation, create an Ingress to forward traffics to headlamp. If there is a DNS record pointing to master WSL, create an YAML:

    apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: headlamp
  namespace: kube-system
spec:
  ingressClassName: traefik
  rules:
  - host: headlamp.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: my-headlamp
            port:
              number: 80

    or in scenerios without DNS record:

    spec:
  ingressClassName: traefik
  rules:
  - http:
      paths:
      - path: /headlamp
        pathType: Prefix
        backend:
          service:
            name: my-headlamp
            port:
              number: 80

    Then kubectl apply -f [YAML_FILE]. After kubeclt apply, visit http://<MASTER_WSL_IP>/headlamp

Configure the Cluster - Workload Shares

  • If there is a node among the two (No1 and No2) which you would like it to share more workloads, label the two nodes first:

    kubectl label node No2 workload=preferred
kubectl label node No1 workload=backup

  • you can set nodeAffinity, podAffinity, podAntiAffinity, topologySpreadConstraints Example deployment:

    apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 5
  template:
    spec:
      affinity:
        nodeAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
      
          # Primary preference
          - weight: 100
            preference:
              matchExpressions:
              - key: workload
                operator: In
                values:
                - preferred
      
          # Secondary preference
          - weight: 50
            preference:
              matchExpressions:
              - key: workload
                operator: In
                values:
                - backup

      containers:
      - name: app
        image: nginx

Configure the Cluster - Common Storage

Create Secrets For Samba Access

  • smb-storage-secrets.yml example: 
    apiVersion: v1
kind: Secret
metadata:
  name: cifs-csi-credentials # 必須與你 StorageClass 設定的名稱一致
  namespace: default         # 必須與你 StorageClass 設定的命名空間一致
type: Opaque
data:
  username: testusername # 貼上你帳號的 Base64 編碼
  password: testpassword # 貼上你密碼的 Base64 編碼

Samba Storage Class

  • Install the SMB CSI driver for Kubernetes from here first.
  • Then create a SMB CSI storage class with examples from here.
  • smb-with-subpath-storageclass.yml Example: 
    apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: smb-with-subpath
provisioner: smb.csi.k8s.io # 確保您已安裝 smb.csi.k8s.io 驅動程式
parameters:
  source: "//[IP_OF_SAMBA_HOST]/[SHARED_DRIVE_NAME]" 
  csi.storage.k8s.io/provisioner-secret-name: "cifs-csi-credentials"
  csi.storage.k8s.io/provisioner-secret-namespace: "default"
  csi.storage.k8s.io/node-stage-secret-name: "cifs-csi-credentials"
  csi.storage.k8s.io/node-stage-secret-namespace: "default"
reclaimPolicy: Delete
volumeBindingMode: Immediate
allowVolumeExpansion: true
mountOptions:
  - dir_mode=0777
  - file_mode=0777
  - uid=8787
  - gid=68787
  - noperm
  - mfsymlinks
  - cache=strict
  - noserverino  # required to prevent data corruption

Create A Persistent Volume Claim/Persistent Volume

  • persistentVolumeClaim.yml Example:

    apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: smb-pvc-k8s
  namespace: default
spec:
  accessModes:
    - ReadWriteMany
  resources:
    requests:
      storage: 10Gi
  storageClassName: smb-with-subpath   # bind via StorageClass
  volumeName: smb-pv-k8s                        # explicitly bind to PV

  • Persistent Volume: persistentVolume.yml Example:

    apiVersion: v1
kind: PersistentVolume
metadata:
  name: smb-pv-k8s
spec:
  capacity:
    storage: 10Gi
  accessModes:
    - ReadWriteMany
  storageClassName: smb-with-subpath   # use your StorageClass
  persistentVolumeReclaimPolicy: Retain
  csi:
    driver: smb.csi.k8s.io
    volumeHandle: smb-pv-k8s   # unique identifier
    volumeAttributes:
      source: "//[IP_OF_SAMBA_HOST]/[SHARED_DRIVE_NAME]/k8s"   # direct path to your share
    nodeStageSecretRef:
      name: cifs-csi-credentials
      namespace: default
